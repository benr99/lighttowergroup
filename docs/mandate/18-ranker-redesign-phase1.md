# 18 — Editorial Ranker Redesign, Phase 1: Architecture and Empirical Audit

**Status:** Phase 1 deliverable. No production code changed.
**Date:** 2026-08-03
**Evidence base:** full regenerated candidate corpus, n=288, all ten scoring
dimensions captured per candidate, plus production run `30817430024`.

---

## 0. Why this document exists

The first live v2 edition (run `30817430024`) ingested 184 candidates, selected
five, and published zero: every candidate was held by a downstream quality gate.
Two of the five were not capital-markets stories at all — a developer-facing
edge-computing explainer and a promotional executive interview.

The immediate cause was a permissive keyword gate. The underlying cause is that
the system has no representation of *what kind of thing an article is* or *what
happened in it*. This document establishes, with measurements rather than
inspection, what the current ranker actually does.

### Method note

Production discards all candidate-level data — only the selected slate reaches
the run artifact. The corpus below was therefore regenerated by re-running
ingestion → classification → scoring locally through the production modules and
instrumenting every candidate. It reproduces production behaviour: production's
selected stories scored 48–64, and this corpus spans 30.7–64.4 with the same
tier assignments.

## 2. Active vs legacy scoring paths

Two complete scoring systems exist. Only one runs.

| | legacy `editorial_intelligence.py` | active v2 `scoring_engine.py` |
|---|---|---|
| Dimensions | 12 | 10 |
| Novelty | computed from event memory | **hardcoded `7`** |
| Routine-event penalty | `-18` | **absent** |
| Archive-repetition penalty | `-18` | **absent** |
| Light Tower right-to-win | scored | absent |
| Explanatory value / human stakes / conversation potential | scored | absent |
| Audience learning adjustment | `±5` from `audience-signals.json` | absent |
| Event memory read | yes | **no** |
| Event memory write | yes (`daily_news_agent`, `edition_manager`) | **no** |
| Sector-specific weights | no | **yes** (a genuine v2 improvement) |

`event-memory.json` holds 262 entries, most recent `2026-07-30` — the day before
v2 became the production path. Confirmed: v2 neither reads nor writes it. The
`archive_records` argument that *is* passed to `select_daily_items` carries
`known_insights` (published source URLs) and is used only for exact-URL dedup.

The run summary for `30817430024` reports `Archive repeats suppressed: 0`. That
is not because there were none; it is because nothing computes them.

**Assessment:** this reads as an unfinished port, not a decision. The
`# Default — requires event memory for real novelty scoring` comment is a TODO
that was never returned to. v2's sector-weight profiles are a real advance and
should be preserved.

| party_significance | 1 | 1 | 10 | 2.95 | 3.56 | **3** | 1 (76%) | 3 values only; bimodal |
| market_impact | 3 | 3 | 9 | 4.08 | 1.45 | 5 | 3 (64%) | weak |

| policy_impact | 2 | 2 | 10 | 2.09 | 0.65 | 5 | **2 (98%)** | **dead** |
| novelty | 7 | 7 | 7 | 7.00 | **0.00** | **1** | 7 (100%) | **constant** |
| source_quality | 3 | 7 | 10 | 6.52 | 1.88 | 4 | 7 (59%) | coarse but live |

**Three dimensions do no ranking work at all** (`novelty`, `editorial_potential`
constant; `policy_impact` 98% single-valued). Two more are near-degenerate
(`cross_sector_impact` has two distinct values; `party_significance` has three).

Effective ranking rests on roughly four dimensions, and the strongest of them —
`financial_magnitude` — is at its floor for 78% of the corpus.

### Consequence 1: dead weight compresses every score

`novelty=7` and `editorial_potential=2` are constants carrying real weight:

| sector | dead share of weight | fixed points contributed |
|---|---|---|
| commercial_real_estate | 18.7% | 8.4 / 100 |
| private_equity | 19.8% | 9.4 / 100 |
| data_centers | 18.1% | 8.4 / 100 |
| energy | 17.5% | 7.9 / 100 |
| banking_credit | 16.8% | 7.6 / 100 |
| fed_macro | 16.8% | 7.8 / 100 |
| local_government | 19.6% | 9.1 / 100 |

Roughly one fifth of the scoring weight is inert and identical for every
candidate.

### Consequence 2: the tier boundaries are unreachable

Observed composite range: **30.7 – 64.4**, stdev 6.62 — 33.7 points of a nominal
100-point scale.

| tier | boundary | count in corpus |
|---|---|---|
| tier_1_must_cover | ≥ 80 | **0** |
| tier_2_strongly_recommended | ≥ 65 | **0** |
| tier_3_useful_coverage | ≥ 50 | 29 |
| tier_4_reserve | ≥ 35 | 226 |
| rejected | < 35 | 33 |

The maximum score the architecture produced across 288 candidates was 64.4 —
**below the tier-2 threshold of 65**. No story can ever be "must cover" or
"strongly recommended". `_ARTICLE_TIERS` admits tiers 1–3, so in practice only
the 29 tier-3 items qualify normally and everything else must arrive through the
`tier_4_reserve` fallback. This explains the recent commits widening that
fallback (`Broaden bounded v2 research fallback`): they are compensating for a
scale that cannot reach its own thresholds.

## 4. The eligibility gate, measured

- 191 / 288 (66%) matched `_CAPITAL_OR_POLICY_ANCHOR`
- 5 / 288 caught by `_NON_EDITORIAL_FORMAT`
- 35 / 288 fully eligible

Keywords that admitted items, by frequency: `data center` (16), `capital` (14),
`power` (13), `fund` (12), `investment` (11), `sale` (11), `investors` (7),
`grid` (7), `housing` (6), `tax` (5), `unit` (5), `financial` (5).

The two known false positives:

| story | admitted by | composite |
|---|---|---|
| Edge Computing vs. Cloud Computing: Choosing the Right Architecture for AI Applications | `data center` | 47.7 |
| Invesco Real Estate's Chase Bolding Talks Market Opportunity | `investment`, `subsidiary` | 60.0 |

In the Invesco case both matched terms appear in the *biographical description of
the interviewee*, not in any transaction. This is precisely the
"incidental-language" failure mode: the gate cannot distinguish an article that
is *about* a capital event from one that merely *contains* a capital-adjacent
noun.

## 5. Duplicate detection: absent

`CanonicalItem.cluster_id` is declared and **never assigned anywhere in the v2
pipeline**. There is no event clustering.

Measured on the corpus: **14 near-duplicate headline pairs**, 10 of them
identical (Jaccard 1.00). `Institutional Real Estate` and `IREI News` syndicate
the same articles under two feed entries.

Two pairs had **both copies eligible**, and would consume two slots of a
three-story edition for one event:

- Slate Property Group $1b SMA — 61.9 (Institutional Real Estate) / 60.0 (IREI News)
- Illinois Teachers' → Partners Group $100m — 55.5 / 53.7

Note the same event receives *different scores* depending on which feed carried
it, because `source_quality` differs. Dedup by URL cannot catch this; the URLs
differ.

## 6. Corpus quality: the upstream constraint

Two measurements bound what any ranker can achieve on current inputs.

1. **131 of 198 feeds returned zero items** in this run. The effective source
   base is far narrower than the configured one.
2. **Summaries are truncated to 600 characters** at ingestion
   (`_truncate_summary`), and no article body is ever fetched.

`financial_magnitude` sits at floor for 78% of the corpus. I initially suspected
a broken money extractor; **that was wrong** — `_extract_amounts` correctly parses
`$1.1B`, `$750 Billion`, `$270m`, `$9.6M` and `$118 million`. The dimension is at
floor because most items genuinely contain no dollar figure within the headline
plus 600 characters of summary.

**This is the single most important constraint in the audit.** No rubric
redesign can score deal economics that are not present in the input. Body
retrieval is a prerequisite for, not an enhancement to, the redesign.

## 9. Proposed target architecture

Replace the single composite score with an explicit, staged pipeline. Each stage
emits a decision plus a rationale, and every stage is independently testable.

```
  ingest  ->  [S0] evidence acquisition
                   fetch article body for shortlist; retain provenance
              [S1] content typing            -> content_type + confidence
                   news / transaction / financing / earnings / policy /
                   monetary_policy / market_data / strategic_action / distress /
                   interview / opinion / research / explainer / marketing /
                   press_release / personnel / duplicate / other
              [S2] event extraction          -> structured event record
                   parties, assets, location, sector, subsector, amounts,
                   rate/spread, scale units, status, evidence spans, missing[],
                   extraction confidence
              [S3] event clustering          -> cluster_id, canonical source
                   ranking unit becomes the CLUSTER, not the URL
              [S4] eligibility by event family -> eligible + reason
                   distinct rules per family; no universal keyword gate
              [S5] importance scoring        -> per-dimension score + rationale
                   within-sector percentile AND cross-sector score
              [S6] penalties & disqualifiers -> explicit, separated
              [S7] portfolio selection       -> soft diversity, hard quality floor
```

### Key design commitments

- **The ranking unit is the event cluster**, not the article URL.
- **Eligibility is per event family.** A Fed decision needs no dollar amount; a
  property trade needs a named asset, parties and scale; an interview qualifies
  only on material disclosure. One universal gate cannot express this.
- **Diversity becomes a soft target with a hard quality floor.** A sector may go
  unrepresented on a weak day. Two stories from one sector are allowed when both
  clear the floor and are materially different.
- **Every number carries a rationale and evidence span.** No unexplained scores.
- **Hybrid, with deterministic verification.** LLM structured extraction is
  permitted for S1/S2, but must return evidence spans quoted from supplied text,
  and deterministic code re-verifies amounts, dates and entities. Cached,
  versioned, reproducible. No black-box "rate this 1–10".

### Proposed rubric (to be calibrated in Phase 2, not adopted blind)

Retain and repair: `financial_magnitude` (feed it real bodies),
`market_impact`, `strategic_relevance`, `source_quality`, `timeliness`,
sector weight profiles.

Replace: `editorial_potential` → **story_richness** (material facts, named
counterparties, quantified scale, tension, consequence — not length);
`novelty` → computed against event memory; `policy_impact` → recalibrated, it is
currently 98% single-valued.

Add: `capital_markets_significance`, `systemic_or_precedent_value`,
`change_from_expectations`, `right_to_win`, `editorial_urgency`,
`evidence_confidence`.

Separate penalties from scores: evergreen-as-news, vendor marketing,
promotional interview, biographical-relevance-only, routine announcement,
recycled date, press-release rewrite, thin evidence, speculation-as-fact,
archive repetition. Some reduce score; some disqualify outright. The distinction
must be explicit in config.

## 10. Migration plan

| phase | scope | risk |
|---|---|---|
| 1a | Observability: persist every candidate with all dimensions, gate decisions and rationales into the run artifact | none — additive |
| 1b | Regression fixtures: lock the two known false positives plus a set of true positives | none |
| 2a | Build labelled benchmark from the 288-item corpus | none — offline |
| 2b | Implement S1 content typing + S2 event extraction behind a flag, shadow only | low |
| 2c | Implement S3 clustering; measure against the 14 known dup pairs | low |
| 2d | Shadow-run new ranker; publish side-by-side comparison | none — no production change |
| 3a | Repair dead dimensions; recalibrate tier boundaries against observed distribution | medium — changes scores |
| 3b | Replace eligibility gate with per-family rules | medium |
| 3c | Replace selection layer (quality floor + soft diversity) | medium |
| 3d | Restore event memory read/write; enable novelty and archive penalties | medium |
| 4 | Evidence acquisition (body fetch) — prerequisite for real gains | higher — network, cost, latency |

Ordering rationale: observability and fixtures first so every later change is
measurable; the ranker changes are shadowed before adoption; body fetch is
sequenced deliberately because it changes cost and runtime.

## 12. Risks, costs, open choices

**Risks**

- A stricter gate could take the edition from 0 articles to 0 articles for a new
  reason. Phase 2 must demonstrate sufficient qualified supply before adoption.
- LLM-based typing/extraction adds per-run cost and latency, and a new failure
  surface. Must degrade to deterministic-only.
- Tier recalibration changes every historical score; comparisons across the
  boundary need a version stamp.

**Costs**

- Body fetch for a ~35-item shortlist: bounded, but adds network time and
  parsing. Needs politeness, caching and per-domain limits.
- Structured extraction on a shortlist rather than all 288 keeps LLM spend
  proportionate. `cost_limits` should be made real before this lands.

**Open choices for you**

1. **Minimum bar vs daily cadence.** If quality is enforced honestly, some days
   will yield fewer than three publishable stories — possibly zero. Is a
   short edition, or no edition, acceptable? This is a product decision and it
   determines how the floor is set.
2. **Body fetch policy.** Fetching publisher article text has robots/ToS
   implications that vary per source. Fetch only where permitted, or rely on
   feeds plus licensed sources?
3. **Interviews and opinion.** Never eligible, or eligible on material
   disclosure? The Invesco piece is the test case.
4. **Scale semantics.** Recalibrate to use the full 0–100 range, or keep the
   current compressed scale and move the boundaries to match?
